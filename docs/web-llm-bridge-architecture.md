# Web LLM Bridge Architecture

## Purpose

This fork narrows Agentify Desktop into temporary Stage 1 scaffolding for a **Web LLM Bridge**. The v1 bridge is ChatGPT-first: it carries text prompts, run/session state, exact-turn results, and bounded ChatGPT-generated output artifacts between callers and an authenticated ChatGPT web session. It is not a local capability or repository-context service. Gemini may follow after the ChatGPT path is proven; existing Claude/other-provider code may remain internally as stale last-known-working implementation but is not part of the v1 public bridge surface.

```text
Codex / Visual Companion / caller
        |
        | delegate prompt
        v
Web LLM Bridge
        |
        | authenticated browser session
        v
ChatGPT (v1)
        |
        | Code MCP
        v
Project
        |
        | tool results
        v
Web LLM
        |
        | structured final result
        v
Web LLM Bridge
        |
        v
Original caller
```

## Responsibility split

| Component | Owns | Does not own |
| --- | --- | --- |
| Code MCP | approved local/project/repository operations | provider sessions or provider DOM compatibility |
| Web LLM Bridge | authenticated ChatGPT sessions, run/turn correlation, constrained mode selection, text transport, and bounded provider-originated output capture | filesystem scanning, repo packing, caller uploads, artifact ingestion, or task acceptance |
| Caller | prompt delegation, policy, and result acceptance | raw browser automation |

The intended ChatGPT-first v1 public operation set is deliberately small:

```text
delegate({ provider: "chatgpt", key, prompt, mode, outputPolicy }) -> { runId, key, state }
status({ runId }) -> run state
result({ runId }) -> rawResponse, completion, selection, artifacts, warnings
stop({ runId })
```

Provider navigation remains internal. The bridge must not expose raw `navigate(any URL)`, arbitrary authenticated-page reading, arbitrary JavaScript execution, caller-local attachment upload, or generic artifact ingestion. Provider-originated files and images are allowed only when they are generated by the exact assistant turn correlated to a run and captured into the bridge-owned bounded cache described in `web-llm-bridge-chatgpt-v1-plan.md`.

## Session and run model

Each ChatGPT conversation has a stable caller-owned key such as `<project>-<task>-chatgpt` (for example, `whisperv-72-chatgpt`). Callers may reuse that key for follow-up work without manually managing browser chats. Each delegation receives a separate unique `runId`; runs sharing a key are serialized and results/status/stop are addressed by `runId`, not by whichever tab is current.

## Delivery path

Stage 1 uses the existing Agentify browser/session implementation as a source donor rather than a permanent product commitment. First narrow the public surface and prove one real delegated loop. Only then extract the small, independently maintained bridge.
